# Contributing

## Workflow

1. Open or reference an issue for material changes.
2. Create a focused branch from current `main`.
3. Add tests and documentation with the implementation.
4. Run the documented quality commands.
5. Open a draft pull request and complete the template.
6. Resolve required checks and review before merge.

## Standards

- Target Python 3.14 and keep type checks clean.
- Preserve the 75% coverage gate while prioritizing meaningful assertions.
- Use Conventional Commit-style summaries.
- Do not commit credentials, personal email, tokens, databases, reports, or message exports.
- Record significant architectural changes as ADRs.
- Keep metrics and logs free of personal-data labels.

Security reports follow `SECURITY.md`, not public issues.
